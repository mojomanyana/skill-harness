# Reviewed learning data workflow

This module supplies data plumbing and a local LoRA workflow. It has not trained an adapter, qualified live JEV quality, enabled automatic collection, or granted runtime authority to model advice. OpenAI Decisions remains excluded. The 24 prospective synthetic cases qualify mechanical plumbing only.

## APIs

All case arrays are the parsed output of `parseCases`; hashes are revalidated on entry. Existing case and label schemas remain unchanged. New object schemas reject additional fields.

- `createStorageConsent({sessionId, decision, interactionId, recordedAt})` returns a consent record. `decision` is `granted` or `declined`; the caller must have obtained the actual explicit user response. `parseStorageConsent(record, expectedSessionId)` validates that exact session. A decline is a valid answer and must not disable JEV advice. No previous session choice may be inherited. The UI is responsible for asking each time JEV is enabled in a new session; this parser cannot prove that a human clicked a button.
- `parseExperiment(cases, manifest)` validates exact ordered case bindings and frozen task/lineage/session split consistency. It also rejects source-record and normalized-input duplicates across splits. This detects exact/formatting duplicates, not semantic paraphrases; the curator must keep related repository/task variants together. Freeze the manifest in a new file before predictions or tuning. Changing a whole group's assignment requires a separately versioned experiment, not an in-place update.
- `reviewLabelEvidence({cases, labels, references})` reads one exact local receipt per independent human/test label. Every receipt must exist and match both its digest and the label/source identity. A provider prediction or AI audit object is rejected. Declared human identity, truth and independence remain review assertions; a typed receipt cannot authenticate its author.
- `importSelectedCase({caseDocument, selection, sessionConsent, experimentEntry})` returns a validated one-case document and provenance receipt. It writes nothing. It requires explicit session storage permission, observed provenance, decision-time/redaction review, a primary public capture binding and exact selected source fragments. It never scans sessions or reads private reasoning. Historical owner IDs must not be guessed to be Pi session IDs: session-to-artifact association is a reviewer assertion unless independently bound by the caller.
- `prepareExport({cases, labels, manifest, consents, labelEvidence, mode})` returns an export and its files without writing. `labelEvidence` is the original reference array, not an asserted prior review result. `mode` is `fixture-demo` or `reviewed-data`. Missing permission, review, labels or split assignment produces explicit exclusions. A missing/changed receipt is an error. Synthetic fixtures are excluded from reviewed training data. Training eligibility requires all input cases eligible, nonempty train/validation/test splits, independent labels, local-training rights and separate training approval.
- `writePreparedExport({prepared, directory})` creates a new private directory and exclusive files. Existing output is refused. Failed partial writes are retained for inspection, never silently deleted or replaced. It checks prepared file hashes and the allowed file names before writing.
- `createLearningFixtures({recordedAt?, set?})` returns case/label documents, a frozen experiment manifest and exact label-receipt bytes. The caller chooses a new output directory and explicitly persists those receipts before export. The default `mechanical` set retains 24 cases with 12 train / 4 validation / 8 test. The opt-in `workflow` set provides 20 synthetic workspace/identity/evidence/routing/reuse cases with 8/4/8 splits; it imports no diagnostic archive. Entire fixture families remain together; neither corpus is a representative production sample.

## Record shapes

Storage consent has exactly `schema:1`, `kind:'decision-session-storage-consent'`, `sessionId`, `decision`, `interactionId`, `recordedAt`, `source:'explicit-user-response'`, and `scope:'selected-session-data-for-lora-review'`. It grants storage only. Remote evaluation, export, actual training and deployment require their own authorization. Supply the current consent state on every export. Duplicate records for one session fail closed; an explicit decline excludes that session. Revocation blocks future imports/exports presented with that state, but this library cannot recall previously copied files or discover omitted revocations.

An experiment is `{schema:1, kind:'decision-learning-experiment', id, frozenAt, entries}`. Each ordered entry is `{caseId, caseHash, taskGroup, lineageGroup, split, sessionId, fixtureOnly, decisionTimeReviewed, redactionReviewed, rights, exportApproved, trainingApproved, reviewer}`. Splits are `train`, `validation`, `test`, or `unassigned`. Rights are `unknown`, `local-export`, or `local-training`. These are explicit reviewed assertions, not legal conclusions. Real cases require a session ID and `fixtureOnly:false`; synthetic cases require null session and `fixtureOnly:true`.

A label reference is `{caseId,path,sha256}`. Its file contains `{schema:1, kind:'independent-decision-label', caseId, caseHash, source, value, labelKind, actor, independent:true, recordedAt, method:{kind,id,version}}`. Source matches the exact case source; labelKind is `human` or `test`; method kind is respectively `human-review` or `deterministic-test`. Existing label `evidenceSha256` hashes these actual receipt bytes. The synthetic fixture receipts bind the executable oracle version and source-function digest. Never convert an AI audit, JEV prediction, or other model judgment into a human/test label.

A selected public import is `{schema:1, kind:'decision-selected-public-input', sessionId, source:{path,sha256}, fragments}`. The primary JSON capture's toolCallId must match the case source.recordId. Each fragment is `{path,sha256,jsonlLine,jsonPointer,start,end,replacements}`. JSONL line is one-based or null; JSON pointer is a selected public string field or null. Start/end are Unicode code-point offsets, zero-based/end-exclusive. Each replacement is `{from,to}` with an explicit placeholder such as `<REPORT_PATH>`. The case input must exactly equal the resulting excerpts joined by two newlines. Retain later outcomes separately; these APIs cannot prove decision-time availability or scan for all secrets.

Evidence reading is Linux-only, using held no-follow directory descriptors and ordinary bounded files (1 MiB each). Ancestor/final symlinks, private-session/credential path components, path changes and hash mismatches are rejected. No original source path is inferred from prose. This is not authentication against a hostile same-user process, an OS sandbox, or a rights grant.

## Training assets and limits

Exports include split JSONL, an exact export manifest, Python training script, pinned direct dependency requirements, an unconfigured model/license/review template and a workflow guide. The manifest binds experiment, label receipt, session consent and exported file hashes. Validation defaults to offline operation. Synthetic exports refuse training. Real exports require a separately reviewed exact manifest, base model revision, local weight hashes, license and architecture-specific target modules. No installation, download, training or deployment occurs during export.

The Python script uses local-only safe weights and no remote model code. It defaults to validation; `--train` is a separate explicit opt-in. It records the selected configuration, seed and resolved environment; direct version pins are not a platform-complete lock and no bitwise GPU reproducibility is promised. Training dependencies and hardware are not qualified by the standard-library validator tests. Only train and validation examples feed the trainer; held-out test bytes are checked but never used for fitting or model selection. A resulting adapter would still require held-out quality/latency and deterministic-baseline comparisons before deployment.

API references were checked against the [PEFT 0.17 quicktour](https://huggingface.co/docs/peft/v0.17.0/en/quicktour), [Transformers 4.57.1 Trainer](https://huggingface.co/docs/transformers/v4.57.1/en/main_classes/trainer), and [local/offline installation guidance](https://huggingface.co/docs/transformers/v4.57.1/en/installation). No live training claim follows from those documentation checks.

## Workflow advisory selections are not qualified learning examples

The optional `jev_advice` extension tool retains `skill-harness-selected-handoff-v1` selections only after current-session storage consent. Their SDK session/tool identities and exact pre-call bytes are bound, while original source binding, redaction and rights remain unassessed. They are unlabeled, `trainingEligible:false` and `exportEligible:false`. This receipt is separate from the pi-daddy public-capture contract and has no reviewed adapter in `verify-sources` or the learning importer. Do not manufacture a public-capture schema, source receipt or independent label from it. Dataset promotion needs a separately reviewed source adapter and the existing independent-label, rights, consent and export/training approvals. See the [workflow behavior](../../docs/DECISION-LEARNING.md#optional-workflow-handoff-advice).
