# Connected inert/retained intervention orchestration

`createInterventionRun(path, input)` / `openInterventionRun(path)` are adapter APIs used by the two-domain replay. This is a separate intervention family: fixed-model comparison is unchanged. Only `kind: inert-retained-v1` exists. There is no live dispatcher, model evaluator, OS sandbox or positive delivery qualification.

Admission freezes the existing intervention manifest, exact case/repetition objectives and station/task-class/risk/population/version scope. An exact finite inert catalogue resolves requested names and supported efforts with no alias guessing or fallback. Its digest and declared lineage are retained. The host supplies explicit requested/canonical proposer, subject and three panel-role declarations, which must match that lookup; unresolved effort or any subject/proposer/panel alias collision is refused before output materialization. Subject identities may repeat across arms. These are validated declarations, NOT independently resolved provider receipts. `configurations()` exposes the exact materialized requested configuration and input digest; observed configuration remains null. Undeclared axes still fail in the existing manifest validator.

A private durable journal owns the manifest. Archive registration prohibits copied/renamed owners from replaying the same experiment. Every arm/cell is claimed before retention; failures leave a visible pending claim, never an automatic retry. Inputs are finite data: at most four arms,64 cells/arm and64KiB/output, with existing journal/JSON/archive bounds. No arbitrary JS, shell, network, session or grant operation is accepted. This does not qualify concurrent live isolation, OS resources, extension-bearing measurement or shadows.

`retain` requires the exact configuration digest and canonical output bytes. Delivery declarations ERROR/NOT-MEASURED prevent panels. For declared PASS, the actual retained bytes must match the **pre-frozen** objective digest. `blind()` exposes only randomized stable labels, case/index and artifact bytes, not cost/configuration or source filenames; artifact content can still leak identity and this limitation is explicit. Archive bytes are reverified before a panel and assessment.

`panel` persists complete per-criterion votes, role declarations and the existing `collapseVotePanel` result. Two primary votes are mandatory. A third is required exactly for a clean split; ambiguous/suspect evidence is retained, not converted to a clean vote. Missing panels/cells remain unresolved/incomplete. This route ingests retained fixture votes, not live judge responses; panel agreement is not accuracy. No model or judge calls occur.

`finish` invokes the existing intervention assessment; cheap objective failures cannot become eligible. Complete eligible comparisons enter the existing durable blind-choice store. Quality choice still precedes configuration/cost reveal. A claimed-but-unacknowledged finish is not automatically retried. `casting(scope)` refuses scope/version mismatch and refuses to reveal until the existing durable quality choice is recorded; the replay writes the table only after that choice. `configurations()` and `finish()` are trusted controller/admin APIs, **not** grader views: only `blind()` is suitable for a blind consumer, and this library does not isolate a malicious same-UID controller. The casting table exposes configurations, conditional eligibility, per-criterion votes, required/retained sample counts and known cost. Real acceptance, escapes, latency and measured samples remain null/unknown/zero where no independently qualified observations exist; zero measured samples is not a zero escape rate. Revalidation conditions are explicit. Routing default remains null, even for one unanimous win.

The replay supplies synthetic role/setting/delivery declarations and votes and saves `casting.json` beside the actual journal/archive/blind output. It exercises the connected orchestration, not model reliability. Remaining external/qualification work includes authenticated role/settings and delivery provenance, approved live effect/resource/transport charters, independent reference labels and actual acceptance/escape/latency observations. Generic Principal payload/host integration remains assigned separately. Original overall CHANGES-REQUESTED is not replaced.
