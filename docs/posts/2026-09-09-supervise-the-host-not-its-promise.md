# Supervise the host, not its promise

An AbortSignal timer inside a blocked JavaScript loop cannot stop that loop. A responsive
parent can observe the original worker process and request occurrence-safe termination.
We reused the existing qualification process utilities rather than weakening Pi admission
or creating another launcher, credential loader, scheduler or accounting store.

The direct-SDK fixture now runs behind that parent observer. Busy-loop timeout, original
cancellation, output overflow and same-group descendant cleanup are tested with actual
inert processes; original producer ownership remains in the worker.

This is useful trusted-host supervision, not arbitrary-code containment. The original
requirements permit an explicit restricted non-shell scope and require total reservations;
they do not prescribe universal cgroups, disjoint provider families or server-token caps.
Keep measured client/lifecycle bounds distinct from unmeasured hard CPU/RSS/PID/money,
crash recovery and live provider identity. Process evidence never grants acceptance.
