# Draft: a preference is not an activation

A comparison can be technically qualified and still leave a person asking: where do I open
it, what did I actually review, and what changes if I say yes?

The retained learning flow now has ordinary CLI and Pi forms over the existing archive,
case reviewer, blind comparison, trust lifecycle and producer registry bridge. No new
transport. No hand-written manifests for everyday review.

The important part is what the buttons do **not** combine:

- Opening a case is deliberate review, not an earned automatic question.
- A detector nomination is not an independent label.
- An excerpt preference is not a complete-artifact quality choice.
- A quality choice is not acceptance or adoption authority.
- Adopt intent and a prepared receipt do not activate a future order.
- Only the original registry's applied receipt records activation or rollback.
- A later outcome can be unknown, changed-requirements or out-of-scope. None is a free
  pass to declare improvement.

The interface constructs scoped inputs and retains decisions. It cannot supply missing
calibration or human judgement. Silence has a reason now; it is not an invitation to lower
the threshold. Reopening does not reset the choice or refill the attention budget.

This is an implementation draft, not a release or efficacy announcement. End independent
review and installed integration precede publication. Existing weather feedback stays
excerpt-only, exactly as it was given.
