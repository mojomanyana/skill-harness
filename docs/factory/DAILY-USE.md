# Factory daily use — 0.15.0/0.25.0 release line

These commands describe the merged 0.15.0/0.25.0 source line. Verify npm/GitHub release coordinates before treating them as installed-release behavior.

1. Declare one current obligation without editing JSON:
   `pi-daddy work add --id <fresh-id> --outcome "<outcome>"`.
2. Start/reload Pi with the matching pi-daddy extension. Ordinary governed delegation records starting and terminal attempts. Runtime completion is not acceptance.
3. With both candidate extensions loaded, run `/grants host <fresh-id>`, then `/grants dashboard` (or the displayed private socket with `pi-daddy-dashboard --host-socket …` when validating an unlinked source package). The host lists `pause-new-dispatch`/`resume-dispatch` and `refresh-current-work`; type only a listed key. Pause affects new ordinary dispatch, not a running child. Stop with `/grants host stop`, which cancels no child.
4. For independent variants use one bounded `delegate_all`, explicit `provider/model`, thinking and correlation `context_id` per child. Omit `completion` for historical wait-for-all behavior. Opt in to primary latency with `completion:"primary", primary:N`; `/grants variants` shows eventual original-session accounting. Freeze the response count first. Requested effort is argv/ledger evidence, not provider-internal reasoning.
5. Retained work can nominate a silent coverage case without a note or facts file. Richer waits, checkpoints, objective failures and reopen facts require their actual evidence.
6. Use Principal 3.2.0's ordinary human report for current/stale/superseded status; `--format human-legacy` is the historical view.

Human acceptance, blind quality choice, adoption and later outcomes remain explicit separate operations; release does not supply them.
