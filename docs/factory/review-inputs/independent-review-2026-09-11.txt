1. Verdict

Partially — and the gap is at the seams, not in the parts. Each repository contains real, tested primitives for nearly every packet, and the scope's negative rules (passive observation, deterministic control, roles separated, quality before cost, missing evidence stays missing) are honored throughout. But the "Done when" criteria of the one-page scope are not met: no real daily session has produced a learning case without manual recording, no real hypothesis has completed archive → experiment → decision → observed outcome, the only executable "factory order" is a fixed SHA-256 digest worker, and the second domain is a synthetic fixture, not a skill set. The delivered product is a set of correct, honestly-labelled building blocks with a scripted replay that wires them together — not yet a factory you can run your day through.

2. What you can actually use today
Retention of governed children (pi-daddy). With PI_GRANTS_EXECUTION_ARCHIVE (and optionally PI_GRANTS_NATIVE_SESSION_ROOT) set, every delegate/delegate_all child records exact tool-call identity, parentage, raw output, check receipts and session location, without touching worker turns. This is wired into the real executor (extensions/execute-child.ts lines ~145–232). Real and usable.
External archive of those files (harness). skill-harness archive ingest|inspect|watch --policy <file> --source <id> ingests with content addressing, checkpoints, restart and explicit coverage gaps. Metadata-only, offline, no model. Usable, but you must hand-write a policy file per source; there is no discovery.
Read-only daily/archive dashboard view via the existing herdr plugin's dashboard-cli (--archive-projection, --work-ledger). Works — but only shows intent if you have a work-v4 ledger, and nothing in production writes one (see F1).
A one-shot Codex-subscription review runner (producer-review-launch.mjs): one frozen review + one isolated advisory judge, bounded to 2 calls. Real; has run live twice (one FAIL, one PASS). Useful as a tool, not as the daily observer.
Principal report --format current-v1: correct red→green / stale / superseded semantics. Opt-in only; default report unchanged.
The examples/factory-local-replay script: demonstrates the whole harness path end-to-end on synthetic worlds. Good for understanding, not for use.

Not usable today: detectors on real sessions, pause-time debriefs from real pauses, steering from a UI (steering is typed as raw JSON lines on the dashboard's stdin), weekly retro on your actual archive, any factory order doing real work, casting tables from real comparisons.

4. Prioritized findings

F1 — Nothing in daily use produces the intent tree. (Blocks P01→P04→P07→P08 as a product.)
appendWorkLedgerEventOnce has exactly one production caller, src/intent-application.ts:87 (dashboard steering), which writes revisions/snapshots. No work_occurrence or work_acceptance is ever emitted by delegation, check-runner or any command. pi-daddy docs/SPEC.md states there is "no first-party production authority caller, v4 CLI/dashboard activation or migration." Consequence: the daily view, detectors and debrief all read a ledger you must author by hand or by fixture; a normal governed session yields retention bytes but no obligations to attach them to. https://github.com/mojomanyana/pi-daddy/blob/7a43219f8f5aa7597034c27b17b68d09222de28c/packages/pi-daddy/src/intent-application.ts#L87

F2 — The only executable effect profile hashes bytes.
contracts/effect-profile/v1/README.md lines 1–7: "not a sandbox for pi, bash, arbitrary JavaScript, model invocations, or writable workspaces… hash at most 16 KiB." P11 experiments and P15 orders therefore only dispatch digest workers. The guide permitted BLOCKED or a restricted profile, so this is not a rule violation — but "bounded autonomous delivery" of any real work is not delivered. https://github.com/mojomanyana/pi-daddy/blob/7a43219f8f5aa7597034c27b17b68d09222de28c/packages/pi-daddy/contracts/effect-profile/v1/README.md

F3 — Detection and debrief never see real work.
Detectors (packages/adapters/src/work-candidates.ts, packages/core/src/work-signals.ts, 63 lines) consume declared facts (checkpoints, violations, priorAccepted, expectedWaits) supplied by the caller; no adapter derives them from retained sessions or tool-call streams. Debrief opens in manual mode only; closing-pause detection is explicitly "not inferred from agent_end or idle flags." Consequence: the "detect, then ask" loop is a data structure, not an observer.

F4 — A bespoke Codex HTTPS/SSE/OAuth stack was built instead of the existing provider route.
~24 of 64 harness commits (codex-https.ts, codex-sdk-transport.ts, codex-subscription.ts, codex-producer-ipc.ts, trusted-host-supervision.ts, plus pi-daddy producer-ipc.ts/ADR-0059) implement TLS pinning, SSE framing, reasoning-summary parsing, diagnostic-word allowlists and an IPC bridge whose child emits {id,sequence:1}. Your amendment said use the Codex subscription; it did not ask for a second HTTP client. The stated motivation (P09 wire attestation) is legitimate, but this is the largest single block of new code and the part most likely to break on a provider change. https://github.com/mojomanyana/skill-harness/blob/c51d57d8badfa3503fc9e5bc52e0ab234e583f93/packages/adapters/src/codex-https.ts

F5 — Parallel infrastructure beside untouched existing seams.
The guide named capture.ts, comparison.ts, pi-json.ts, execution-trace.ts, run.ts, screen.ts, adjudication.ts, vote-panel.ts as seams to extend. None is modified. The harness adds ~3,700 source lines in new modules; pi-daddy adds ~4,800 (plus ~6,300 test lines). Preserving frozen contracts was correct, but the result is two comparison families, two archive concepts (execution-trace vs evidence-archive) and two case models rather than one extended system.

docs/factory/BUILD-REPORT.md at PR head is byte-identical to the P00-era baseline: P00 DONE, P01/P09 BLOCKED, everything else TODO. The real tracker, evidence and receipts are in an unpublished working copy. Reviewers reading the PR cannot reconcile packet state.
