# 4 — One-page scope: a factory that learns

**Outcome:** Daily development and bounded autonomous delivery share one system. You set outcomes and boundaries; the stack records work, detects opportunities and tests improvements.

**Ownership:** pi-daddy controls; skill-harness learns; pi-daddy's herdr dashboard plugin presents; skills supply domain conventions. Extend existing grants, ledgers, delegation, capture and comparisons. Add no new product. Proposed scope, grounded in steps 1–3.

## Build in this order

1. **Make intent explicit — pi-daddy + skills.** Create a versioned tree of goals, obligations, dependencies and delegations. Join sessions/branches, attempts, artifacts and configurations. Bind acceptance to exact intent/artifact revisions; supersede it when they change. Skills define stations and acceptance; assume no Principal phases, tools or evidence types.

2. **Retain observable work — skill-harness + pi-daddy.** Read streams, session files and ledgers externally; retain governed child sessions through execution setup. Join observations to outcomes. Define archive access, retention and redaction. Show coverage gaps; observer overload must never delay workers.

3. **Show status and enable steering — dashboard + pi-daddy.** Separate runtime, acceptance and evidence coverage; show current/overall state and a short factual narrative. Let you revise, reprioritise or pause work. Log authority and revisions; steer at safe boundaries. Status reads never steer.

4. **Detect, then ask — pi-daddy + skill-harness + dashboard.** Nominate structural drift, stalls, loops, escaped defects and exemplars. Start with silent calibration; earn amber visibility and questions. At closing pauses ask at most five; defer unanswered cards. Expected behaviour and uncertainty are valid labels. Manual notes remain optional.

5. **Close the learning loop — skill-harness.** A weekly frontier-model retro reads only the archive. Propose hypotheses for skills, subagents, routing, grants, casting and your workflow, with predictions and disproof conditions. Follow: accept investigation → promote scenario → freeze evaluation → edit → compare → decide adoption → observe outcomes. Include boundary and held-out cases.

6. **Compare variants — pi-daddy + skill-harness.** Run N isolated variants of models, effort, skills or prompts; N=2 shadows never delay the primary. Bound total resources. Judge eligible outputs blind before revealing cost. Preserve fixed-model comparisons; add separate casting comparisons. Record applicability, uncertainty and evidence.

7. **Earn trust and adopt narrowly — skill-harness + pi-daddy.** Track precision per detector/adjudicator version and scope, sample sizes and unresolved labels; sample unflagged work. Use silent / ask / retire with predeclared thresholds. Adopt tested changes within supported scope, with rollback and escape tracking. Pin active work to approved revisions.

8. **Enable autonomous dispatch — pi-daddy.** Execute eligible nodes under an approved charter: outcome, acceptance, effects, resource/recovery limits, stopping rules and reserved decisions. Deterministic policy controls dispatch and grants. Return consequential exceptions to you; continue independent authorised work where permitted.

## Gates and boundaries

Observation adds no agent context or worker turns. Proposer, subject and judge require distinct verified model identities and separate contexts. Model judgment stays advisory until calibrated trust and explicit scoped policy permit using its evidence; no model calls enter the control path. Precision never creates authority.

Invalid delivery measurement yields **unmeasured**, not efficacy claims. Resolve affected extension-measurement gaps before qualifying those experiments. Unattended operation requires enforceable effect boundaries and budgets; grants and cooperative leases alone are insufficient.

**Preferred cleanup:** Test removal of redundant code, tests, prompts and obsolete documentation while preserving obligations. Keep historical verdicts; clarify current applicability. Measure first-pass acceptance, escapes and human attention within comparable work classes. Scrum work remains out of scope.

**Done when:** A real daily session produces a confirmed learning case without manual recording; an independent experiment supports or refutes its hypothesis; any adoption remains traceable and reversible; a bounded factory order progresses and returns reserved decisions. Demonstrate the same contracts with a non-development skill set.
