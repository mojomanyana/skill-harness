# Durable weekly investigations and scoped trust

These are connected, **offline** paths under the existing archive command and adapter package. They do not launch models, install a runtime, grant permissions, schedule an OS job, or authenticate a human. Use a new directory under an existing private owned parent. Explicit creation is separate from reopening; do not delete a failed job to retry it.

## Weekly investigation

`createWeeklyInvestigation(directory, input)` freezes week, population, policy, immutable archive-reader snapshot and selected **actual confirmed case decisions**. `input.cases` contains explicit v2/v3 batch, case manifest and decision IDs. The existing selected-batch reviewer is read; a caller's `confirmed: true` is not a substitute. The candidate population must match. Recreating the same job is read-only/idempotent; a changed selection is refused.

`openWeeklyInvestigation(directory)` exposes this connected lifecycle:

1. `run({kind:'inert-v1', requests:[...]})` claims the job durably **before** processing requests. The finite, bounded interpreter accepts only `{tool:'archive.read',manifestId}` and a final `{tool:'hypothesis',proposal}`. It actually invokes the existing bounded archive reader and persists read identities and advisory output. The hypothesis must cite exactly the selected cases, population and snapshot, after an allowed read. Both model-call budgets must be zero.
2. The host is inert **data**, not injected executable JavaScript. Bash, filesystem/session/grant mutation, Herdr sockets, arbitrary network, unknown requests, access outside the approved manifests, getters and non-plain data are rejected. There is no dispatcher or transport for them. Denial records failure; a missing terminal receipt means claimed/unknown, never permission to rerun. This is an enforced finite interpreter—not OS confinement for arbitrary JavaScript or an already-qualified live model host.
3. `approve(authority)` checks the existing investigation-only authority. `preview(specPath, scenario)` uses the actual existing spec preview. `promote(preview, authority)` revalidates current case decisions and exact privacy-preview consent, records an effect claim, calls the existing spec writer and records its result. Exact completed replay is read-only. A pending/failed acknowledgement is not automatically retried or erased.
4. `freeze({spec,rubric,judgePolicy,heldout,configuration,skill}, authority)` reads actual bounded file bytes, requires the promoted spec and distinct canonical candidate/evaluation paths, and persists the existing evaluation freeze. `previewEdit(text)` yields an exact candidate-edit digest; `edit(text, authorizedDigests)` checks current frozen bytes and explicit edit authority before changing only that candidate. There is no edit path in the inert host.
5. `evaluation()` rechecks case decisions, all frozen evaluation files and the authorized candidate digest. It returns the real linked case IDs/freeze, but **executionReady:false**: no model/effect qualification or screening result has been fabricated. A changed rubric/judge/heldout/configuration invalidates the evaluation; a changed candidate outside the permitted edit fails too.

The supervisor lives inside existing harness operation: `archive weekly --state /private/job --request request.json`. The closed envelope is `{operation,input,authority}`. Operations: `create`, `run`, `inspect`, `approve`, `preview`, `promote`, `freeze`, `preview-edit`, `edit`, `evaluation`. For `preview`, input is `{specPath,scenario}`; other inputs mirror the adapter method. Read-only operations can use null input/authority. Request files are bounded, duplicate keys refused, and expanded/cyclic values bounded. These are explicit operator requests, not commands supplied by the inert host.

## Trust lifecycle

`createTrustLifecycle(directory, input, [trustPolicyDigest(input)])` stores a separately approved predeclared component/version/population, cohort of retained source manifests, sampling seed/count and exposure policy (or null). It samples only unflagged, non-tuning incidents in deterministic SHA order **before** accepting labels. This is exploratory sampling, not an unbiased-population guarantee. Creation cannot revise an existing policy/cohort or reset attention.

- `predict(prediction)` joins a prediction to the frozen flagged cohort and exact component/split.
- `correct(priorId, replacement, reason)` appends a new prediction and lineage. It never changes original prediction bytes, reuses the old ID, changes the frozen split, or inherits an old label for a corrected prediction.
- `outcome(reference, [trustOutcomeDigest(reference)])` requires an independently supplied exact permission and retained reference evidence. Prediction correctness and sampled-unflagged defect labels are distinct kinds. Unrelated or unsampled references are refused; contradictory labels remain unresolved/conflicted.
- `previewCaseOutcome(predictionId, caseReference)` / `linkCaseOutcome(..., [preview.digest])` connect to the **actual** v2/v3 selected-batch reviewer. The case manifest and detector scope must match the prediction. Superseded confirmation is removed from current confidence, while the original outcome/history remains recorded.
- `inspect(now)` calls the existing `calibratePredictions` on current prediction/reference joins, keeping positive precision separate from unflagged misses and tuning exclusions. Eight correct, two incorrect and three unresolved is **8/10 plus3 unresolved**. Adjudicator approval/rejection remain separate. It returns attention use, retirement and exposure history for a host/dashboard read model.
- `expose(id, now)` recomputes against the immutable predeclared policy and atomically records silent/ask/retire plus its evidence tip. A question ID is idempotent (`replayed:true`); attention is not charged twice, and reopening never refills it. Retirement persists; changed versions/policies require explicit new scope rather than silent inheritance. This applies an **attention reservation**, not proof a human was shown a question. Actual pause/presentation acknowledgement belongs to the separately authorized host integration.

`archive trust --state /private/trust --request request.json` uses the same envelope. Operations: `create`, `predict`, `correct` (`{prior,prediction,reason}`), `outcome`, `inspect` (numeric clock), `expose` (`{id,now}`). The adapter additionally exposes the actual case-outcome linkage. Policy/reference permission lists come from the independent trusted operator, not prediction fields; IDs are not human authentication.

## Persistence and remaining boundaries

An immutable archive-local registration binds each weekly key/policy to exactly one store and input. Creating a second directory with the same authority or reopening a copied journal is refused; it cannot refill attention or claim the same week twice. Exposure clocks cannot move backwards. This is not hostile same-UID rollback protection for the registration itself.

Both paths share one bounded, private append-only hash-chain/CAS journal: no-follow regular files, private owned directories, exclusive writer lock, exact prior tip, fsynced records, occurrence-checked lock release and explicit errors. Two real processes racing the same prior cannot both win. A stranded lock, torn journal, replaced directory or failed acknowledgement is an error/pending state; there is no TTL takeover, truncation, automatic recovery or hidden retry. Pure advisory reads never launch work. This assumes a cooperative trusted filesystem/owner, not hostile same-UID rollback resistance or a general process sandbox.

These connected inert paths address the repository portions of OAR-SPEC-003/005. Live model transport/confinement, independent real labels and policy authority, authenticated deployed pause/presentation, model-backed screen/experiment qualification and later real production outcomes remain separately unqualified. The dependent demonstrator must pin corrected actual producer order code; synthetic authorities cannot close live P16. Original overall CHANGES-REQUESTED and historical failures remain unchanged.
